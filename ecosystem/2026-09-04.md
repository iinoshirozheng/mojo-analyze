## Networking / FFI: the strongest ecosystem delta today

### `tamnd/mojo.httpx` — Brotli/Zstd via runtime-loaded FFI, plus safer proxy-environment semantics

Repository: https://github.com/tamnd/mojo.httpx

Two substantial changes landed today.

Commit `da9fc412` adds Brotli and Zstandard streaming decoders loaded by library name at runtime, like the existing zlib path. Instead of duplicating four decoder loops, zlib/brotli/zstd backends are normalized to one small `_Step` contract (`consumed`, `produced`, `ended`, `stalled`) and share the same output/ratio limits. The implementation deliberately avoids one-shot APIs that require trusting attacker-controlled decoded sizes. `Accept-Encoding` is assembled from codecs that actually loaded, so missing native libraries reduce advertised capability instead of failing the whole client.

Commit `8c68dcb5` adds `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY` under `trust_env`, including CIDR-aware `NO_PROXY`, deterministic lower-case precedence, and the classic `httpoxy` defense: upper-case `HTTP_PROXY` is ignored when `REQUEST_METHOD` indicates CGI context.

Why interesting: this is mature systems-library work rather than a protocol demo. It combines optional native FFI, capability-based degradation, streaming decompression safety limits, environment compatibility and security rules. The reported full suite reached 1817 tests on three machines plus parity testing.

Potential `mojo-analyze` experiment: a small FFI boundary benchmark comparing streaming decompression through Mojo bindings vs a C/Rust baseline on identical compressed blocks, separating library time from binding/dispatch overhead. It should include tiny inputs where FFI overhead dominates and large inputs where codec work dominates.

Sources:
- https://github.com/tamnd/mojo.httpx/commit/da9fc412a325d7b1799a13584f7d7d78a4f9247f
- https://github.com/tamnd/mojo.httpx/commit/8c68dcb59c1436eeabdb24f77ee55b31553ca126

### `codetalcott/mojo-http` — removing unnecessary GIL ownership exposes a 50–100% throughput win

Repository: https://github.com/codetalcott/mojo-http

A particularly useful performance investigation landed around release 0.17.1. The server's offloaded event loop used to release Python thread state only while blocked in `kevent`/`epoll_wait`, then reacquire the GIL to parse and send data that did not touch Python. Instrumentation found the re-acquire blocked for roughly **36–45% of wall time** under several loaded paths.

The new design detaches the loop from Python thread state for the entire serving loop and attaches only at the explicit fallback that actually invokes Python. The project's A/B notes report examples such as ASGI executor throughput moving from about **67.5k to 101–109k req/s at 16 connections**, **84k to 158k at 256 connections**, and bare WSGI with one pool thread from **71k to 140k req/s**. A separate fairness probe then guards against GIL convoying among worker threads after the loop stops acting as an accidental fairness pump.

Today the project re-soaked and re-recorded benchmark artifacts for the detached-loop shape, including CPython 3.13.6 runs.

Why interesting: this is a strong example of measuring an interoperability boundary instead of guessing from language-level code. The optimization is not “faster parsing”; it is removing runtime ownership from a thread that does not need the foreign runtime.

Potential `mojo-analyze` experiment: add an interop microbenchmark track that repeatedly crosses Mojo↔Python thread/GIL boundaries with no-op, tiny-work and medium-work callbacks. Measure when attach/detach cost dominates and when batching work across a boundary wins. Keep it outside the canonical five-category suite until the comparison contract is stable.

Sources:
- https://github.com/codetalcott/mojo-http/commit/0766272b83d8fb9a4929fbbbe4207b2cf3bafd83
- https://github.com/codetalcott/mojo-http/commit/443977aeeea3ded2a51aaa6157e230c81979a6f8

## Newly surfaced projects worth tracking

### `Hundo1018/wgpu-mojo` — WebGPU bindings with real compute + graphics lifetime constraints

Repository: https://github.com/Hundo1018/wgpu-mojo

`wgpu-mojo` provides Mojo bindings to `wgpu-native`, targeting the Vulkan / Metal / DX12 backend set with RAII GPU objects, compute helpers and interactive rendering examples.

A recent repair to its headline compute example is technically instructive: compile-only CI missed three runtime failures — read-only storage binding mismatch, GPU buffers being dropped after only their raw handles remained, and attempting to map a STORAGE output directly instead of staging it through a MAP_READ/COPY_DST buffer. CI now runs headless examples instead of merely compiling them.

Why interesting: this is one of the clearer Mojo graphics paths that does not depend on Mojo's native GPU backend. It also exposes ownership/lifetime and staging-transfer costs that a benchmark can measure cleanly.

Potential experiment: a WebGPU compute dispatch benchmark through Mojo vs a minimal C/Rust wgpu-native binding, split into (1) pipeline creation, (2) dispatch-only with resident buffers, and (3) dispatch + staging readback. This would complement MAX-native GPU work with an external graphics/compute API boundary.

Sources:
- https://github.com/Hundo1018/wgpu-mojo
- https://github.com/Hundo1018/wgpu-mojo/commit/7a0cd52eae501f44b7e16b7e90a8f9209cfd747d

### `conorbronsdon/mojo-xml` — a useful stable-toolchain + nightly-drift CI pattern

Repository: https://github.com/conorbronsdon/mojo-xml

The parser itself is a pure-Mojo XML DOM with CPython `ElementTree`-style behavior. More relevant to this repository is its CI policy: after unpinned nightlies turned a green repository red without any local commit, it pinned normal CI to a known-good compiler and added a separate weekly advisory run against the latest nightly. On Mojo 1.0 release, the normal lane moved to stable 1.0 while the nightly drift check remained.

Why interesting: this is exactly the operational shape `mojo-analyze` needs for longitudinal compiler testing. Canonical results should be reproducible from a fixed toolchain; upstream drift should be detected in a distinct lane rather than mutating the baseline underneath it.

Potential experiment/infrastructure change: implement stable canonical CI plus a non-canonical pinned-nightly differential lane that records compile success, checksum agreement and runtime deltas without overwriting `results/results.json`.

Sources:

### `ehsanmok/flare` — a broader pure-Mojo networking stack to keep on the systems watchlist

Repository: https://github.com/ehsanmok/flare

`flare` combines HTTP/1.1, HTTP/2, HTTP/3/QUIC, WebSocket, TLS, TCP/UDP/Unix sockets, DNS and gRPC around a non-blocking reactor. Recent work fixed a subtle text-boundary problem: untrusted response/request bytes must either be lossily converted to a well-formed string where protocol semantics allow it, or rejected when the protocol (WebSocket text frames) requires valid UTF-8.

Why interesting: it is another signal that Mojo networking projects are now hitting production-style invariants — hostile bytes, FFI boundaries, lifetime rules and protocol conformance — rather than only throughput demos.

Potential experiment: not yet a canonical benchmark. If networking is added later, first isolate one parser/codec primitive with exact cross-language byte output before attempting full server throughput.

Sources:
- https://github.com/ehsanmok/flare
- https://github.com/ehsanmok/flare/commit/c6f008470586d531757eeee87642e0efe32f6a34

## Research candidates

1. **Stable canonical + nightly differential CI** — highest-confidence infrastructure candidate. Pin both; never let nightly overwrite canonical results. Track compile/checksum/runtime/codegen deltas.
2. **Mojo↔Python runtime-boundary cost** — isolate attach/detach/GIL crossings across no-op and batched work to quantify when interop boundary cost dominates.
3. **Streaming codec FFI overhead** — zlib/Brotli/Zstd-like streaming calls across Mojo vs C/Rust, with equal native codec backend and tiny→large block sweep.
4. **WebGPU dispatch/readback decomposition** — pipeline creation vs resident-buffer dispatch vs staging readback through `wgpu-native`.
5. **Networking parser primitive before server benchmark** — choose a byte-exact HTTP/HPACK/UTF-8 primitive and checksum-gate it before attempting end-to-end requests/sec comparisons.
