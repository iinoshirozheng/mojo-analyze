### O02 — Advanced fusion stops rebuilding per-capture `TileTensor` accessors

**Recent development, 2026-09-26.**  
Immutable commit: https://github.com/modular/modular/commit/652563cbab5cd4dac55db67027ab23cd44f760c9

The graph compiler now emits `ManagedTensorSlice` pointer loads/stores for advanced-fusion captures instead of rebuilding a `TileTensor` and routing through dedicated strided load/store primitives. The commit reports that generated output remains identical while eliminating a per-kernel JIT compile-time regression caused by Mojo instantiation/optimization work. **Evidence:** implementation diff and commit rationale inspected; the compile-time claim is upstream-authored, not independently reproduced here. **Research angle:** compile the same family of strided/broadcast fusion kernels on revisions immediately before/after this commit and separate JIT compile time from execution time.

### O03 — Paged-buffer gather no longer copies the entire source buffer

**Recent development, 2026-09-26.**  
Immutable commit: https://github.com/modular/modular/commit/baeafbda35bb6fa173c91bccd49712b5553a4e59

MAX fixes a regression where loading a mutable buffer and then gathering selected rows could allocate/copy the entire source buffer on every execution, including paged-KV-cache style access. The load now folds into the gather so requested rows are read directly. **Why it matters:** this is a concrete example where a seemingly local graph-lowering choice changes memory traffic and peak allocation enough to cause OOMs. **Research angle:** a synthetic large-buffer/small-gather fixture can measure bytes moved, peak memory and execution time independently.

### O04 — DeepSeek-V4 chat/reasoning/tool-call serving path lands

**Recent development, 2026-09-26.**  
Immutable commit: https://github.com/modular/modular/commit/9931921cf330e2fd0e559af5e4c75b4f3cbfa2de

MAX adds a DeepSeek-V4 reference-compatible chat template path plus reasoning and tool parsers, with checked-in reference test vectors. The architecture can now serve `/v1/chat/completions` with checkpoint-specific prompt semantics and tool-call decoding. **Evidence:** implementation/changelog/test additions inspected. This is primarily a correctness/serving-semantics development, not a performance result.

## Repository discoveries

### R01 — `Benny-Nottonson/Mojo-Marathons`
**Benchmark/community corpus; newly discovered historical project.** https://github.com/Benny-Nottonson/Mojo-Marathons  
Pure-Mojo, standard-library-only optimization competition; published history includes a July 2024 matrix-multiplication challenge. Historical compatibility needs migration. **Evidence:** README inspected. **Experiment:** revive one submission with a fixed numerical oracle and compare codegen without changing the algorithm.

### R02 — `manatlan/sudoku_resolver`
**Cross-language algorithms; newly discovered existing project.** https://github.com/manatlan/sudoku_resolver  
Same recursive backtracking Sudoku strategy across C, Python, Mojo, Nim, Go, Java, JS and Rust over 1,956 grids, with “same weapons” and specialized lanes. Timings are author-reported and Mojo uses Python for stdin. **Experiment:** move I/O outside timing, verify solved grids byte-for-byte, then compare recursion/string cost.

### R03 — `jiel/laplacian_filters_benchmark`
**Image processing; newly discovered technical backlog.** https://github.com/jiel/laplacian_filters_benchmark  
Laplacian edge detection on BSDS500-derived grayscale PGM images, with interactive display separated from batch timing. Mojo code targets the old 24.x era. **Experiment:** port the convolution kernel, preserve image/checksum equivalence, and time scalar/SIMD separately from parsing.

### R04 — `mzaks/compact-dict`
**Data structures/storage; newly discovered existing project.** https://github.com/mzaks/compact-dict  
Compact hashmap with string/generic variants and compile-time controls for key-count width, key-offset width, deletion metadata and hash caching. The README’s ~10× stdlib claim is author-reported. **Experiment:** fixed corpus; report bytes/entry, rehash count, inserts and lookups across representation switches.

### R05 — `mikowals/dynamic_vector.mojo`
**Reference semantics/container design; newly discovered historical prototype.** https://github.com/mikowals/dynamic_vector.mojo  
Reference-aware DynamicVector from Mojo 24.1 demonstrating reference item access, lifetimes, slices and reduced copies/moves. README explicitly says it is obsolete because many ideas moved into the language/stdlib. **Experiment:** reconstruct nested-update behavior with modern `List`/references and inspect copy/destructor traffic.

### R06 — `mzaks/mojo-flx`
**Binary serialization/storage; newly discovered existing project.** https://github.com/mzaks/mojo-flx  
FlexBuffers implementation with aligned binary data, random access, heterogeneous vectors/maps and no mandatory parse/unpack step. **Experiment:** identical encoded document/access sequence against a reference implementation, separating construction, allocation, lookup and traversal.

### R07 — `helehex/moplex`
**Numerical types; newly discovered historical project.** https://github.com/helehex/moplex  
Generalized complex, dual and split-number families; README pins Mojo 24.5.0. **Experiment:** port a minimal dual-number derivative kernel and verify against analytic/finite-difference references before codegen inspection.

### R08 — `shivasankarka/SciJo`

SciPy-inspired pure-Mojo layer atop NuMojo with numerical differentiation, integration, interpolation, FFT and constants. Dependency/toolchain compatibility must be rechecked. **Experiment:** FFT size sweep with NumPy oracle, numerical error reported separately from throughput/allocation.
