**Research angle:** use nightly only for a single mechanism-level differential with the stable compiler and identical source/checksum contract.

### O02 — GPU launch closures continue moving from comptime parameters to runtime values

**Lane:** recent development — 2026-09-19.  
**Sources:**  
- fused FP8 RMSNorm: https://github.com/modular/modular/commit/f56e0845d4edc39c3eccec1760a96c0e9656a40a  
- allgather+RMSNorm: https://github.com/modular/modular/commit/caea71e0f8452e0c03e464d76fc372c2f8aa36df

Two kernel changes remove legacy `@__parameter`/capturing-closure launch plumbing and pass unified closures as runtime values. The FP8 RMSNorm change constrains closure values to `RegisterPassable` and passes them through the kernel struct so enqueue can bit-copy them; the public API and arithmetic stay unchanged. The allgather/RMSNorm dispatch similarly turns launch closures into value arguments.

**Why it matters technically:** this is a concrete compiler/runtime boundary for Mojo 1.1+'s closure migration. It may affect specialization/code size and launch ABI even when arithmetic is identical.

**Research angle:** compare generated kernel variants / compile size for legacy-parametric versus unified-value closure plumbing on a minimal launch, without treating compile success as a runtime-speed claim.

### O03 — MAX replaces fixed 8 MiB model-input backings with declared workload bounds

**Lane:** recent development — 2026-09-19.  
**Source:** https://github.com/modular/modular/commit/de3527631348e880314202fb9db6ab509cdb49a0

`ModelInputBuffers` now declares maximum shapes from real batching dimensions (`max_batch_size`, sequence length, token budget, chunked-prefill policy, and data-parallel degree) instead of giving every named input an arbitrary 8 MiB backing. The commit reports a default Llama-3 token/row-offset pair shrinking from two 8 MiB buffers to roughly 64 KiB and 1 KiB, while an overrun now raises rather than silently allocating a fallback.

**Why it matters technically:** capacity should derive from semantic bounds, not a magic byte ceiling. The DP multiplier is part of the correctness contract because the processor flattens replicas into one ragged stream.

**Research angle:** model-input memory benchmarks should report logical maximum shapes, lazy per-device allocation, and graph-capture behavior separately from steady-state throughput.

### O04 — Jenga KV cache moves to one coordinator per leaf

**Lane:** recent development — 2026-09-19.  
**Source:** https://github.com/modular/modular/commit/89a4d1740e5739bb840bfbe5c97616e07240dc1e

The KV cache manager now keeps one coordinator per cache leaf rather than per attention group. Prefix-cache residency is passed as a positional mask and leaf-specific `longest_hit()` rules handle full, sliding-window, recurrent, and scratch shapes; this removes duplicated reconciliation logic and avoids rereading each leaf's prefix cache on every reconciliation pass.

**Why it matters technically:** heterogeneous cache shapes need a common semantic oracle for joint reuse, otherwise an optimization can silently overstate reusable prefix depth.

**Research angle:** a future cache benchmark should validate hit depth against a shape-aware oracle before measuring lookup/reconciliation cost.

### R02 — `bgreni/Kelvin`: type-safe dimensional analysis

**Repository:** https://github.com/bgreni/Kelvin  
**Domain:** numerical/scientific / metaprogramming  
**Lane:** newly discovered existing project; repository created 2025-04-02 and last pushed 2026-08-14 when observed.  
**Evidence:** repository metadata, package catalog and author material inspected; catalog targets Mojo 1.0.0.

Kelvin encodes physical dimensions in types so invalid unit combinations are rejected by the type system rather than discovered numerically at runtime.

**Why it matters:** it is a useful non-ML example of Mojo's compile-time parameter system and a good place to separate compile-time type machinery from runtime arithmetic cost.

**Experiment angle:** compare equivalent unit-safe and raw-scalar kernels at optimized codegen level; first verify dimensional correctness at compile time rather than timing only successful paths.

The proposal explains why compile-time-only literal state moved into parameters rather than runtime storage. It is a useful concrete case of Mojo's “comptime domain should stay comptime” design and helps read generated IR without mistaking literal machinery for runtime work.

## 4. Deep-dive picks

1. **Unified-closure kernel ABI:** Sep-19 RMSNorm/allgather changes are a clean compiler/runtime boundary because arithmetic is intentionally unchanged while closure transport changes.
2. **Semantic buffer bounds:** MAX's new model-input declarations turn capacity from an arbitrary constant into a checkable workload contract and intentionally fail loud on overruns.
3. **Interop diversity:** `hellomojo` and `monpy` expose two very different ABI boundaries (R/C and CPython buffer protocol) that can be decomposed into fixed crossing cost, ownership and bulk compute.
4. **Scientific correctness:** Ish and Kelvin show two complementary oracles—reference alignment results and dimension types—where correctness can be established independently of performance.
5. **Benchmark infrastructure:** `bench.mojo` is worth comparing methodologically with this repository because estimator/calibration behavior itself can change a performance conclusion.

## 5. Research candidates

1. **Category D in-memory scanner codegen — selected for today's research phase.** Inspect the already-isolated scanner hot loop and reduce one byte-access/bounds/loop-control difference to a causal intervention before another parser rewrite.
2. **Stable 1.0/1.1 `List` growth differential.** Reproduce geometric-growth impact with allocation/copy counts plus timing, not just wall clock.
3. **Unified-closure launch codegen.** Minimal legacy-parameter versus runtime-value closure case, measuring compile size/specialization first.
4. **Kelvin zero-cost check.** Compare dimensional wrapper versus raw scalar optimized IR/assembly under a fixed arithmetic kernel.
5. **R/Mojo ABI microbenchmark.** Measure fixed `.Call`/C-wrapper overhead separately from bulk buffer work, gated by round-trip correctness.
