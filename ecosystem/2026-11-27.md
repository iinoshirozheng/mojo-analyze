### Data systems and bioinformatics

1. **[magmalake/parquet.mojo](https://github.com/magmalake/parquet.mojo)** — newly discovered / recent packaging delta, columnar storage. README describes native page/header/level/value decoding, projection by field ID, nested reconstruction, statistics and bloom filtering, and Arrow C Data Interface with release callbacks. Distinct base and full-codec packages; full adds C-backed codecs. [Nov 26 release merge](https://github.com/magmalake/parquet.mojo/commit/25ee8c7e9cdb3dabb668611ee88f3c69e0ee8146) pins sibling dependencies and 1.3.0.dev2026112605, not evidence of a speedup. README and diff inspected; conformance claims author-reported. Try nested nullable columns and release callback lifetime against PyArrow; measure decode separately from projection.

2. **[magmalake/objectstore.mojo](https://github.com/magmalake/objectstore.mojo)** — new discovery, systems/storage FFI. Common FileIO for local data, range reads and S3; native interface uses a libcurl transport through a small compiled shim and runtime dynamic loading. [Nov 26 v0.5.2 merge](https://github.com/magmalake/objectstore.mojo/commit/bdf6f25ca99fcc1951b4b347e5849e4927e7774e) is version metadata only, not a substantive algorithm improvement; counted for the new interface profile, not release alone. README and diff; nightly channel, exact runtime compatibility untested. Try a local HTTP range server oracle (bounds, short reads, status); separate TLS/network from byte copies.

3. **[MoSafi2/BlazeQC](https://github.com/MoSafi2/BlazeQC)** — new discovery, sequencing quality control. README provides separate package build and source/package test commands; depends on BlazeSeq. [Census record](https://mojourney.dev/repos/MoSafi2/BlazeQC) identifies a March 2026 snapshot and 0.26.1 lock era; no claim about current compatibility or measured speed. Early research library. Try a known FASTQ fixture and independently computed per-position quality histogram before throughput.

4. **[MoSafi2/rapidgzip_mojo](https://github.com/MoSafi2/rapidgzip_mojo)** — new discovery, compression/interoperability, found from BlazeQC dependencies. Thin C shim over C++ rapidgzip exposes file decompression, allocation/caller buffers and index building, not pure Mojo decompression. README says limited API and only Linux x86-64 tested; exact current compiler pin not verified. Candidate: Python gzip byte-for-byte oracle, cold index construction separated from warm range reads and allocation.

5. **[MoSafi2/BlazeSeq](https://github.com/MoSafi2/BlazeSeq)** — new discovery in this recent window / different technical deep dive: parsing-mode and ownership semantics. Documented Mojo 1.2, borrowed FASTQ views versus owned records versus SoA GPU batches; FASTA and FAI metadata; current RapidgzipReader is a compatibility wrapper while external rapidgzip dependency disabled. README only, not reproduced; throughput goals are author claims. Compare view versus owned mode with identical validation and file-cache state; test truncated reads and lifetime rules.

6. **[mzaks/mojo-csv](https://github.com/mzaks/mojo-csv)** — historical project discovery distinct from Phelsong's mojo_csv. RFC 4180-style builder, opt-out escaping and optional SIMD tokenization. [25.5-era update](https://github.com/mzaks/mojo-csv/commit/ed6c01c022335b2b484754a9b980f9f25e4c8c5b) signals older syntax; date not checked, no current build claim. Compare scalar/SIMD only after matching CRLF, doubled-quote, embedded newline and UTF-8 behavior; never compare escaping on versus off for arbitrary strings.

## Technical reading / backlog

Official original technical documentation, version 1.2.0, observed Nov 27; publication/revision dates not shown, not classified as today's articles. Each addresses a distinct implementation question rather than counting overview and its subpage twice.

- **[Compile-time evaluation](https://mojolang.org/docs/manual/metaprogramming/comptime-evaluation/)** — elaborator/interpreter execution and expansion limits; unrolling may increase compile cost and binary size. Try runtime loop vs comptime expansion with identical checksum and assembly.
- **[Traits](https://mojolang.org/docs/manual/traits/)** — contracts include required methods, associated types and compile-time values. Read for benchmark backend seams: use negative compile fixtures and compare static dispatch with equivalent handwritten work.
- **[Python interoperability](https://mojolang.org/docs/manual/python/)** — separates CPython dynamic-library calls from compiled Mojo exports to Python; documented 3.10–3.14 interop range. Useful for measuring object conversion separately from kernel time, not evidence of arbitrary Python syntax support.
- **[Testing](https://mojolang.org/docs/tools/testing/)** — TestSuite discovery, assertions and explicit negative error paths; failing test suite exits nonzero. Useful for old pytest plugin output-compatibility and an independent numeric oracle.
- **[Packaging](https://mojolang.org/docs/tools/packaging/)** — isolated rattler-build recipe, precompile, dependencies and test phase; older example compiler pins should not be confused with current docs version. Compare build/install/import boundaries on stable vs nightly with exact dependency graph.

## Deep-dive picks (not extra entries)

- **Byte-path ownership:** BlazeSeq modes and Arrow release callbacks provide separate questions about borrowed data lifetime, allocation and transfer. Avoid conflating parser throughput with decompression or Python boundary.
- **Metaprogramming cost:** Blade masks and compiler evaluation documentation suggest measuring compile time and executable size as well as runtime.
- **Fail-closed interfaces:** Prism validates flags before side effects; pytest subprocess contracts should likewise distinguish failure from an empty or malformed result.
- **Mixed-language provenance:** rapidgzip, objectstore and Furnace rely on non-Mojo implementations in critical paths; compare boundaries and exact libraries, not headline language rankings.
