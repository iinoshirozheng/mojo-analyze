## Repository discoveries — 16 distinct owners

### Compiler verification, runtime, developer tooling

1. **[MojoProof](https://github.com/Robertboy18/MojoProof)** — owner \`Robertboy18\`; **recent development (Nov 22)**; formal verification/compiler. The README and [proved scope](https://github.com/Robertboy18/MojoProof/blob/main/docs/proved.md) describe Lean proofs about the GPU-kernel LLVM IR emitted by Mojo, for some elementwise kernels and bounded matmul, with quantified schedule claims and explicit premises. Its [trusted-base inventory](https://github.com/Robertboy18/MojoProof/blob/main/docs/TRUST.md) notably excludes **downstream LLVM/NVPTX/ptxas/driver/hardware**, so “proved output IR under assumptions” is *not* “all deployed GPU behavior formally proved.” Evidence: README + trust/proof docs + five issue reports; not independently built. **Study:** use a tiny correctness oracle for a selected GPU kernel, and distinguish formal model scope from actual device execution.
2. **[ArgMojo](https://github.com/forfudan/argmojo)** — owner \`forfudan\`; **new discovery**; developer CLI. Mojo builder-style and struct-declarative argument parsing, help/completion and nested commands; author links actual use by Decimo CLI. README specifies Mojo 1.2 and package presence. Evidence README only; current build not verified. **Study:** negative fixture matrix for mutually exclusive/duplicate command flags, separated from CLI initialization costs.
3. **[mojo-lambda-runtime](https://github.com/fourlexboehm/mojo-lambda-runtime)** — owner \`fourlexboehm\`; **new discovery**; serverless/runtime. Implements AWS Lambda custom \`provided.al2023\` HTTP runtime via libc sockets, with arm64 deployment scaffold. README describes packaging **after** community-channel publication, so channel availability is not verified. Evidence README only. **Study:** Runtime API request/framing oracle and cold-start vs handler timing, not HTTP latency alone.
4. **[heat-url](https://github.com/joeressler/heat-url)** — owner \`joeressler\`; **new discovery**; standards/parser tooling. Separate WHATWG URL recovery and RFC 3986 URI parsing paths, Unicode IDNA/percent-encoding in Mojo; differs deliberately on \`https:example.org\`. Evidence README only; no independent cross-browser tests. **Study:** differential corpus with URL Standard and RFC 3986 expected outcomes; keep two semantics distinct.

### Numerical, FFT, scientific verification, physical AI

5. **[hackathon-fft](https://github.com/martinvuyk/hackathon-fft)** — owner \`martinvuyk\`; **new discovery with dated older evidence (Nov 2)**; CPU/GPU mixed-radix FFT. Author benchmarks compare cuFFT and other libraries, but implementation, precision and batch conditions must be checked before speed claims. Importantly, README reports GPU suite compile attempts lasting ~1,000+ s, device-wide \`ptxas\` failure and a full 1D build OOM (~25 GB RAM). Inspected [time-test-compiles.sh](https://github.com/martinvuyk/hackathon-fft/blob/main/fft/scripts/time-test-compiles.sh): it times builds and **does not run tests**. **Study:** separate build cost, failure rate, FFT correctness and device runtime; prime lengths are useful controls.

Typed \`Quantity\` dimensions with rational conversion ratios and SIMD typed widths. 9. **[MSL: Mojo Scientific Library](https://github.com/mojomath/MSL)** — owner \`mojomath\`; **new discovery**; numerical/scientific. ## Four deep-dive picks (synthesis, not counted again)

- **MojoProof + upstream issues:** useful model of how formalized contracts expose boundary bugs, but trust boundary ends at emitted IR. Reproduce one small CPU layout/gcd issue on pinned toolchain before treating five issues as verified regressions.
- **FFT build-time versus runtime:** FFT project documents GPU test *compilation* exhaustion and PTX assembler errors. A benchmark that excludes codegen cost alone misses the practical reproducibility budget.
- **Data portability correctness:** Balsa semantic-validation opt-in, protomojo conformance fixture, iceberg snapshot delete semantics and Polars Arrow FFI show four distinct oracle classes: file integrity, wire compatibility, transactional state, and ownership/lifetime.
- **Audio-vs-video runtime:** MMMAudio owns DSP, MAV wraps FFmpeg; separate sample computation, host bridge, encoding and user-visible delivery rather than one total “Mojo is faster” statistic.
