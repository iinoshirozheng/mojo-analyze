### Systems, data and developer tools

- **R01 [Mojoverse](https://github.com/sstadick/mojoverse)** — sstadick; new discovery/migration angle. The standalone [mojopt README](https://github.com/sstadick/mojopt) redirects development here; one profile, not two. Workspace consolidates typed CLI, binary-safe buffered I/O, SIMD byte search, radix sorting, interval structures, BAM/BGZF and FASTA/FASTQ, pthread workers, raylib bindings and experimental Rust binding generation. Main pins 1.3.0.dev2026111705/Pixi 0.80+, stable/1.2 is separate; relative package dependencies resolve to the same revision. ExtraMojo is a known dependency/migration relation, not a separate novelty claim. Useful probe: compile an identical byte-search fixture with a coherent revision per lane and verify exact offset parity.
- **R02 [EmberSerde](https://github.com/bgreni/EmberSerde)** — bgreni; new discovery distinct from EmberJson. Reflection-driven serialization separates format traits from application types; a serializer handles primitives and stateful containers. README targets Mojo 1.1.0 and its JSON example deliberately omits real escaping. Test nested structs, enums and Unicode against a real format implementation; distinguish reflection compile cost from runtime conversion. Not a complete JSON implementation based on the example.
- **R03 [flare-routegen](https://github.com/joeressler/flare-routegen)** — joeressler; new developer-tool discovery. Top-level structured comment directives become deterministic compile-time route registrations; check mode compares exact generated bytes and refuses to overwrite unmarked source. It is not an HTTP framework. CI pins Mojo 1.0.0/Pixi 0.70.2 and Flare main (documented API range 0.10); floating dependency is a reproducibility limitation. Test generation reproducibility and stale/invalid directive failure, not HTTP throughput.
- **R04 [mojo_csv](https://github.com/Phelsong/mojo_csv)** — Phelsong; new tabular parser discovery. Row-major cells, row views, reader from pre-split cells, delimiter/quote/thread configuration; default uses logical cores minus two. Native parser currently depends on MAX for parallelization; catalog max>=26.3,<27.0. Compare parser-only and row-view costs with fixed thread counts; Python csv oracle for embedded quotes/newlines, empty cells and ragged rows.
- **R05 [Pyroquet](https://github.com/idlab-discover/pyroquet)** — idlab-discover; new storage profile, not yesterday's Snappy project. Version 0.1.1 source release targets Linux x86-64/Mojo 1.0.0; pinned Pixi/uv and sibling NuMojo/Snappy checkouts. Numeric columns expose shared mutable arrays while retaining nulls; native Snappy but GZIP/ZSTD call C codecs. Refuses existing output destinations. [Release-tag checkout](https://github.com/idlab-discover/pyroquet/tree/v0.1.1) per README, release date not established. Test Arrow/PyArrow null masks and bit-exact numeric roundtrip; separate decode, editing and codec work.
- **R06 [Professor](https://github.com/gsmyridis/professor)** — gsmyridis; new profiling discovery in this window. Lexical named regions aggregate nested inclusive/exclusive metrics; custom instruments and Linux perf_event/Apple hardware-counter wrappers documented. Profiling disabled by default unless compile define is provided; catalog pins Mojo 1.0.0. Counter permissions and instrumentation overhead vary; timestamp counter is not automatically CPU time. Candidate: compare region-level CPU-clock instrument with no-op overhead and checksum equality for checked Span.

### Numerical, ML and text

- **R07 [Poly Mojo](https://github.com/Spellbound-Mojo/poly_mojo)** — Spellbound-Mojo; new exact-algebra profile (APN dependency previously covered). Dense/sparse polynomial arithmetic, exact and enclosed roots, Gröbner bases, CAD and streaming certificates; independent checkers distinguish factor products, membership and enclosure claims. README targets 1.0.2 with Mojo 1.2.0 on Linux x86/ARM and Apple Silicon. No proof checker run here. Reconstruct factors and verify rational interval root counts before comparing solve vs certificate-check cost.
- **R08 [Nabla](https://github.com/nabla-ml/nabla)** — nabla-ml; mixed-language discovery. Python-facing autodiff/trace and distributed SPMD execution use MAX and custom Mojo kernels, not a pure-Mojo Python replacement. Main alpha requires Modular nightly; GPU routes differ by vendor; documented Torch/JAX test dependencies. Compare fixed shape matmul gradient against NumPy finite differences and separate trace/compile/device time.
- **R09 [Knap](https://github.com/olaflaitinen/knap)** — olaflaitinen; explicit deep dive on correctness gates rather than prior tokenizer throughput ideas. Byte BPE with hand-written pretokenizer and generated Unicode tables; reference tiktoken parity, all seven encodings, corpus and fuzz gates claimed by author. Pinned Mojo 1.0.0; no native Windows toolchain; README packaging statement differs from current catalog, so package installation status not independently confirmed. [Artifact DOI](https://doi.org/10.5281/zenodo.22701440) linked by author, not inspected. Test exact token IDs on a frozen adversarial Unicode corpus and distinguish corpus verification from shared-runner smoke timing.
- **R10 [mojo_datetime](https://github.com/martinvuyk/mojo_datetime)** — martinvuyk; new calendar library profile (distinct from FFT work and Morrow). Native configurable TimeZone/Calendar/leap data, release tags encode compiler versions; author explicitly calls default transition and leap-second data best-effort. Catalog lists Mojo 1.0.0; README describes older beta and nightly versions. Validate ambiguous/skipped wall times against frozen IANA tzdata, comparing identical semantics rather than unsupported leap-second behavior.

### Cryptographic and ID utilities

- **R11 [crypto](https://github.com/lczerniawski/crypto)** — lczerniawski; new hash library discovery. README lists MD5/SHA-1/SHA-256 and random integer generation, with Span input and digest conversion. WIP, catalog Mojo 1.0.0. MD5/SHA-1 are legacy, not recommended for collision resistance; no security audit verified. SHA-256 known-answer fixtures at padding boundaries 55/56/63/64/65 bytes before throughput; avoid conflating hex conversion with digest core.
- **R12 [mcrypto](https://github.com/aelxtpt/mcrypto)** — aelxtpt; new cryptography discovery. Batched primitives, known-answer/negative/state/path registry and native multi-architecture behavioral workflow described; README v0.2.0 pins Mojo 1.0.0. Author discloses AI assistance and possible errors; no assurance of security or constant-time behavior. Compare public SHA-256 vectors, report batch vs single-message shape; no security claims from timing alone.
- **R13 [nanoid](https://github.com/cirello-py/nanoid)** — cirello-py; older new discovery, configurable alphabet and compile-time length, default documented 12 characters. README uses legacy magic workflow; official catalog MAX 25.3, modern build unknown. Check output length/alphabet and rejection-sampling bias with controlled inputs; randomness/security cannot be inferred from uniqueness in a small sample.

## Original technical readings / backlog

Dates refer to publication where established. Official manuals are mutable, original revision date unknown, observed Nov 25; version compatibility must be rechecked.

- **T01 [MojoBench](https://aclanthology.org/2025.findings-naacl.230/)** — Raihan, Santos, Zampieri, April 2025 NAACL Findings (preprint Oct 23 2024). Abstract describes HumanEval-Mojo and a code-generation model; its performance metric is model task success, not compiled program speed. Older compiler-era tests need migration and execution before applying to today's codegen agents. Abstract inspected; no dataset replication.
- **T02 [Fine-tuning LLaMA 2 interference: comparative language implementations](https://arxiv.org/abs/2502.01651)** — Hossain et al., Jan 30 2025. Abstract describes Apple M1 Max inference comparisons across SDKs/languages. Read to distinguish model implementation, quantization, runtime and device from language effects; abstract only and pre-1.0, no comparability conclusion here.
- **T03 [A Comprehensive Review of Mojo](https://ieeexplore.ieee.org/abstract/document/10883176)** — ICMCSI Jan 7–8 2025, IEEE posting Feb 20; author names not established in this pass. Abstract surveys Endia, Lightbug, Basalt and LLM.mojo. Historical adoption snapshot, not fresh performance evidence; useful baseline for comparing ecosystem maturity claims across releases.
- **T04 [Lifetimes, origins and references](https://mojolang.org/docs/manual/values/lifetimes/)** — Modular language manual. Compiler tracks symbolic ownership/mutability; Span carries borrowed origin; wildcard origins weaken exclusivity and can extend destruction. Good starting point for checked Span vs unsafe pointer comparisons where lifetime changes are confounders; docs not codegen proof.
- **T05 [Materializing compile-time values](https://mojolang.org/docs/manual/metaprogramming/materialization/)** — Modular manual. Explicitly materializing a complex collection inside a loop can repeatedly allocate; static self-contained arrays can use global_constant instead. Compare identical table lookups with hoisted vs repeated materialization, observing generated allocations rather than assuming comptime implies zero runtime cost.
- **T06 [Bencher API](https://mojolang.org/docs/std/benchmark/bencher/)** — Modular stdlib reference, original date/version not independently fixed. Configurable warmup, batching, throughput and CPU/GPU timing documented. Compare timer boundaries and overhead with existing harness before treating measurements as equivalent; no new measurement.

## Deep-dive picks (not extra entries)

1. Mojoverse: synchronized source revisions and stable/nightly lanes are particularly useful for reproducible dependency builds.
2. Professor: choose the metric that tests the hypothesis; a hardware timestamp counter is not proof of on-core execution time.
3. Pyroquet: nullable data and codec choice must be held constant across readers.
4. Poly Mojo: certificate verification costs are part of the workload only when the compared implementations produce equivalent evidence.
5. EmberSerde: compare compile-time specialization cost independently of serialized bytes and runtime cost.

## Ranked research candidates

1. Canonical arm64 checked-Span scanner: region-scoped thread CPU clock plus wall time, randomized order, checksum, same codegen, clock overhead calibration. Native arm64 Mojo environment required.
2. Professor instrument calibration against OS thread CPU time, including deliberate sleep and busy work, pinned toolchain.
3. SHA-256 padding-boundary vectors and separate digest/hex conversion; pinned 1.0.0.
4. Pyroquet null-mask and codec roundtrip with PyArrow independent oracle.
5. Compile-time table materialization versus hoisted runtime allocation, equal output and assembly comparison.
