Matrix-focused structures, views/strides and decomposition-oriented linear algebra. Current 1.1/1.2 compatibility needs re-verification. **Candidate:** fixed matrix primitive with a NumPy/BLAS oracle and stride/codegen inspection.

### R04 — `mojomath/stamojo`
**Statistics; newly discovered existing project.** https://github.com/mojomath/stamojo  
Stdlib-only statistical foundation with special functions, distributions, descriptive statistics, correlations and tests. README SciPy-reference validation is project-authored evidence. **Candidate:** difficult-tail CDF/PPF correctness before speed.

### R05 — `guidorice/mogeo`
**Geospatial/interchange; technical backlog.** https://github.com/guidorice/mogeo  
Archived pre-alpha exploration of GeoArrow-style layout and alternate geometry representations on an older Mojo toolchain. Its durable lesson is the importance of representation-conversion and zero-copy costs.

### R06 — `msaelices/mojo-regex`
**Regex/automata/comptime; newly discovered current project.** https://github.com/msaelices/mojo-regex  
Hybrid DFA/NFA/PikeVM/LazyDFA design plus experimental compile-time automaton construction. Headline Python/Rust comparisons are author-reported. **Candidate:** same pattern/text/output, runtime construction versus embedded comptime automaton, reporting build cost separately.

### R07 — `thatstoasty/mist`
**Terminal/dev tooling; newly discovered current project.** https://github.com/thatstoasty/mist  
ANSI-aware styling, profile degradation, text transformation, and compile-time style construction; README targets Mojo 1.1. **Candidate:** byte-parity fixtures then comptime-versus-runtime style construction.

### R08 — `thatstoasty/floki`
**Networking/FFI; newly discovered current project.** https://github.com/thatstoasty/floki  
Requests-like client over libcurl plus a small C compatibility layer for a libcurl call shape Mojo does not directly expose. It is not a pure-Mojo transport. **Candidate:** loopback test separating Mojo preparation, boundary calls, and transfer.
